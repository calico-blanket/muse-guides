MuseでGitHubにプッシュする手順

GitHubアカウントは自分で作り、Museと接続して、承認はその都度自分でする。あとのリポジトリ作成とコミット、プッシュはMuseに頼めます。初めてMuseを使う人が、プッシュまでたどり着くための手順書です。

第1章まず知っておいてほしいこと

  • GitHubアカウントを作るのは、あなた自身です。Museはアカウントを作れません。
  • アカウントを作っただけでは足りません。MuseとGitHubを「接続」して初めて、Museがリポジトリを作ったり、ファイルを入れたり（プッシュ）できるようになります。
  • パスワードやトークンを、チャットでMuseに教える必要は一切ありません。聞かれても教えないでください。
  • プッシュするファイルは、誰が作ったものでも構いません。自分で書いたもの、Museが作ったもの、他の道具で作ってMuseに渡したもの、どれでも同じ手順です。

第2章手順

2.1GitHubアカウントを作る

GitHubのサイトで自分で登録してください。メール確認まで済ませて、パスワードは自分で管理してください。スマホにGitHubアプリを入れておくと、途中で出る本人確認の承認が楽になります。

どのサービスでも、アカウント作成の流れはだいたい共通です。

  1. 受け取れるメールアドレスを用意する（確認メールや確認コードが届きます）
  2. ユーザー名とパスワードを決める（パスワードは他のサービスと使い回さず、自分で管理します）
  3. 公式サイトから登録して、届いたメールで本人確認を済ませる
  4. できれば二要素認証（2FA）を設定して、認証アプリを用意する

GitHubの場合の具体的な手順は、次の折りたたみの中にあります。必要な人だけ開いてください。

GitHubアカウントの作り方（開いて読む）
  1. ブラウザで github.com を開き、右上の「Sign up」を押します。
  2. メールアドレスを入力して「Continue」を押します。
  3. パスワードを作って入力し、「Continue」を押します。GitHubのパスワードは、15文字以上、または8文字以上で数字と小文字を含むものが必要です。
  4. ユーザー名（Username）を決めて入力し、「Continue」を押します。使えるのは半角の英数字とハイフンだけで、先頭と末尾にハイフンは置けません。この名前が、リポジトリのURL（github.com/あなたの名前/リポジトリ名）にも出ます。
  5. お知らせメールの希望（Email preferences）を選ぶ画面が出たら、どちらでも構いません。「Continue」を押します。
  6. 「Verify your account」という確認（パズルなど）が出たら、画面の指示に従って済ませて「Create account」を押します。
  7. 登録したメールアドレスに確認コード（launch code）が届くので、その数字を画面に入力します。これでアカウント作成は完了です。
  8. ログインできたら、仕上げに二要素認証を設定しておくのがおすすめです。右上の自分のアイコンから「Settings」→「Password and authentication」→「Enable two-factor authentication」を選び、認証アプリ（GitHubアプリでも可）で設定します。途中で出る本人確認の承認にも使うので、スマホにGitHubアプリを入れて、同じアカウントでログインしておいてください。

パスワードと確認コードは、Museを含む誰にも教えないでください。入力するのは、GitHubの公式サイトと公式アプリの中だけです。

2.2MuseとGitHubを接続する

Museのチャットで、こう送ってください。

GitHubを接続したい

出てきたリンクから認可を進めてください。途中で「Museが使ってよいリポジトリを選ぶ」画面が出ます。ここが大事なところです。

この画面は、公開範囲（Public / Private）の話ではありません。Publicは誰でも見える、Privateは限られた人だけ見える、という決まりとは別に、「あなたのリポジトリのうち、どれをMuseに触らせてよいか」を決める画面です。Museは、ここで許可されたリポジトリだけを読んだり書いたりできます。

選び方は2つあります。

選び方内容向いている人
All repositories
（全部許可）		 今あるリポジトリも、これから作るリポジトリも、全部が対象になります。新しくリポジトリを作るたびに追加する手間がありません。 触られたくないリポジトリがなく、手間を減らしたい人。初心者には簡単な方です。代わりに、Museが触れる範囲は一番広くなります。
Only select repositories
（選んだものだけ）		 チェックを入れたリポジトリだけが対象になります。新しく作ったリポジトリは自動では対象にならないので、使うときにその都度追加が必要です。 見られたくない・触られたくないリポジトリがある人。範囲を絞れる分、安心な方です。

どちらを選んでも、後から同じ画面で変更できます。迷ったら、見られたくない・触られたくないリポジトリがあるかどうかで決めてください。なければ「全部許可」、あれば「選んだものだけ」です。

「リポジトリが見えません」と言われたら

接続が終わっても、もしMuseに「リポジトリが見えません」と言われたら、故障でも、非公開（Private）のせいでもありません。「選んだものだけ」にしていて、そのリポジトリがまだ許可リストに入っていないだけです。そのときは、Museにこう送ってください。

リポジトリを選ぶ画面のリンクをください

出てきた画面で「選んだものだけ」にそのリポジトリを追加するか、「全部許可」に切り替えてください。

2.3プッシュを頼む

接続できたら、下の文をそのまま送ってください。

GitHubに新しいリポジトリを作って、手元にあるファイルをプッシュしてください。
・リポジトリ名：内容に合ったものを提案して、進める前に見せてください
・公開範囲：Public（誰でも見える）／ Private（自分だけ）のどちらか
・ブランチ：main
・入れるファイル：指定したファイル全部
作業を始める前に、リポジトリ名と入れるファイルの一覧とコミットメッセージを
見せてください。承認カードが出たら私が承認します。
終わったら、リポジトリのURLと、ファイルが本当に入っているか確認した結果を教えてください。

リポジトリ名は自分で決めなくて大丈夫です。半角英小文字とハイフンで作るなどの決まりがあるので、Museに提案してもらって、良いかどうかだけ確認するのが簡単です。すでに名前が決まっている場合は、その名前を書いてください。

公開範囲だけは自分で決めてください

Publicは誰でも見えます。パスワード、APIキー、個人情報、日記など見られたくないものが入っている場合は、必ずPrivateにしてください。

2.4更新するとき

2回目以降は、短くて大丈夫です。

この修正を、リポジトリ（名前）の main ブランチにプッシュして。
変更するファイルと内容を先に見せてから、承認カードを出して。
終わったら確認して、結果を教えて。

第3章承認について

大事な注意点です。先に読んでおいてください。

  • リポジトリ作成やプッシュなど、「書き込む操作」のたびに承認カードが出ます。1回承認すればずっと許可、にはなりません。
  • 例えば、リポジトリ作成で1回、最初のプッシュで1回、別の日の更新プッシュでまた1回、という頻度です。まとめて1回でプッシュすれば、承認も1回で済みます。
  • 承認する前に、カードと事前に見せてもらった内容（リポジトリ名、ファイルの一覧、ブランチ）が合っているか確認してください。
  • 承認カードが時間切れになって止まることがあります。その場合、作ったものはMuseの手元に残っているので、チャットで「反映して」と一言送れば、作り直さずに続きから反映できます。

第4章Museがプッシュできる範囲

  • 得意なのは、HTML、CSS、JavaScript、Markdownなどのテキストファイルです。初めて作るホームページや説明書のページは、だいたいこの範囲に入ります。
  • コネクター経由のプッシュは、ファイルをまとめて1つのコミットにする方式です。目安として、2,000ファイルまで、合計16MBまで、文字コードはUTF-8です。

次のようなものは、コネクターでは扱えないことがあります。

  • ファイルの削除を含む変更（GitHub側に古いファイルが残ります）
  • 画像や動画などの大きなバイナリファイル
  • パソコン側のGitの履歴をそのまま移すこと

扱えない場合は、MuseがブラウザでGitHubの画面を直接操作する形に切り替えることがあります。そのときは、GitHubアプリに届く番号の確認など、本人確認のお願いが出ることがあります。画面の番号と一致しているか確かめてから承認してください。

第5章終わったら

MuseからリポジトリのURLが届きます。自分でも開いて、目的のファイルが並んでいるか見てください。そこまで確認できたら完了です。
